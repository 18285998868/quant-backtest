## 1. 架构总览

```text
CSV / Parquet
     |
     v
+----------------+     +----------------+     +----------------+
| data           | --> | engine         | --> | metrics        |
| 加载/校验/哈希 |     | 时间线/撮合/账本|     | 收益/回撤/指标 |
+----------------+     +----------------+     +----------------+
                              ^                       |
                              |                       v
                       +----------------+     +----------------+
                       | strategy       |     | report         |
                       | 内置/trait     |     | JSON/HTML      |
                       +----------------+     +----------------+
                              ^
                       +----------------+     +----------------+
                       | sweep          | --> | walkforward    |
                       | 网格/并行/top-K|     | 窗口/选参/OOS  |
                       +----------------+     +----------------+
                              ^
                       +----------------+
                       | system         |
                       | 线程/内存预算  |
                       +----------------+
```

部署形态:单个 Rust crate,产出 `quant-backtest` 二进制和同名库。模块之间通过第 3 节的类型契约通信,不共享全局状态。

有意不做的架构:微服务、插件动态加载、事件总线、数据库、分布式调度。单机单进程足够。

## 2. 模块划分与职责边界

| 模块 | 职责 | 不负责 | 对外接口 |
| --- | --- | --- | --- |
| `config` | TOML 解析、默认值、校验、配置哈希 | 数据校验、交易逻辑 | `RunConfig`, `SweepConfig`, `InstrumentSpec` |
| `data` | CSV/Parquet 读取、规范 schema、排序/去重校验、数据哈希 | 复权、时区转换、缺失值填补 | `load_universe() -> Universe` |
| `model` | bar、标的、账户、持仓、订单、成交、结果等纯数据类型 | 业务规则 | 公共结构体 |
| `strategy` | `Strategy` trait、内置策略、参数状态 | 下单、账本、成本 | `Strategy::on_bar()` |
| `engine` | 时间线、目标权重差、下一根开盘撮合、止损/止盈、现金/保证金、成交记录 | 指标公式、HTML | `run_backtest() -> BacktestResult` |
| `metrics` | 收益、风险、回撤、交易、成本、月度、DSR | 数据加载、交易决策 | `compute_metrics()`, `drawdown_analysis()` |
| `sweep` | 参数笛卡尔积、任务并行、结果排序、top-K、聚合 | 单次回测内部逻辑、窗口切分 | `run_sweep() -> SweepResult` |
| `walkforward` | 窗口生成、训练集选参、OOS 拼接、窗口汇总 | 单次回测内部逻辑、指标公式 | `run_walk_forward() -> WalkForwardResult` |
| `system` | CPU/内存检测、线程数决策、内存预算 | 业务逻辑 | `detect_capacity()`, `resolve_threads()` |
| `report` | `ReportData`、JSON schema、HTML 模板、ECharts 内嵌 | 指标计算 | `write_json()`, `write_html()` |
| `cli` | 参数解析、命令分发、退出码、日志 | 业务逻辑 | `quant-backtest <command>` |

依赖方向:`cli -> walkforward/report`;`walkforward -> sweep -> engine`;`report -> metrics`;`engine -> strategy/metrics -> model`;`data -> model`;`sweep/walkforward -> system`。`metrics` 不依赖 `engine`,只接收净值/成交切片,便于单测。`walkforward` 只编排单次回测与扫描,不复制引擎逻辑。

## 3. 契约

契约在本节冻结。确认后任何改动必须新增变更说明(见第 8 节),并同步测试与追溯表。

### 3.1 数据契约

规范长表 schema:

| 列 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `ts` | Int64 | 是 | UTC epoch 毫秒;bar 的收盘时刻;同一 symbol 内严格递增 |
| `symbol` | Utf8 | 是 | 稳定标识;同一文件内一致 |
| `open` | Float64 | 是 | 有限且 > 0 |
| `high` | Float64 | 是 | 有限且 >= max(open, close, low) |
| `low` | Float64 | 是 | 有限且 <= min(open, close, high),> 0 |
| `close` | Float64 | 是 | 有限且 > 0 |
| `volume` | Float64 | 是 | 有限且 >= 0;0 表示不可交易 |
| `quote_volume` | Float64 | 否 | 保留,首版不参与计算 |

约定:

- bar 区间为 `[start, end)`,`ts` 对应 `end`;日线为 UTC 自然日收盘。
- 文件按 `symbol, ts` 升序;加载器仍会校验,不信任输入顺序。
- 同一 `(symbol, ts)` 不得重复。
- 单标的允许缺失 bar,成交顺延到该标的下一个可用 bar;多标的必须共享同一 `ts` 序列,任一标的缺失即报错,不做填补。
- 美股使用复权价;加密/外汇使用原始报价。复权方式由 `data-reader` 负责,引擎不猜。
- 一次回测的所有标的必须共享同一时间线(相同 `ts` 序列),且同一计价货币;否则报错。
- 周期由 `run.toml` 的 `timeframe` 声明,不从 bar 间隔猜;一个文件只放一个周期。首版只实现 `1d`;`1m/5m/15m/30m/1h/4h/1w` 的完整实现放后续阶段 M1。
- 年化因子优先用 `periods_per_year`;未填时按 `timeframe × asset_class` 推导:加密 365 天、美股 252 天 × 6.5 小时、外汇 252 天 × 24 小时。推导值是近似,报告记录实际使用值。
- CSV 接受 RFC3339 UTC 或 epoch 毫秒两种 `ts`;Parquet 固定 Int64 毫秒。

### 3.3 策略契约

```rust
pub struct TargetPosition {
    pub symbol: SymbolId,
    pub weight: f64, // 目标名义价值 / 权益;负数做空
}

pub struct PositionView {
    pub symbol: SymbolId,
    pub qty: f64,          // 带符号;空头为负
    pub avg_entry: f64,
    pub mark: f64,
    pub stop: Option<f64>,       // 绝对价格
    pub take_profit: Option<f64>, // 绝对价格
}

pub struct MarketContext<'a> {
    pub ts: Ts,
    pub index: usize,
    pub universe: &'a Universe,
    pub cash: f64,
    pub equity: f64,
    pub positions: &'a [PositionView], // 长度 = 标的数,空仓 qty=0
}

pub trait Strategy: Send {
    fn on_bar(&mut self, ctx: &MarketContext<'_>, out: &mut Vec<TargetPosition>);
}
```

约定:

- 引擎在每次调用前 `out.clear()`;策略只 push,不清空。
- 同一 symbol 出现多次时,最后一个生效。
- 未出现在 `out` 中的 symbol 表示"目标不变",不是"平仓";要平仓必须显式给出 `weight = 0`。
- 止损/止盈触发后,引擎把该 symbol 的内部目标权重重置为 0;策略必须给出新的目标才会再入场。内置趋势策略只在信号变化时输出,避免刚止损就立刻反向补回。
- `weight` 必须是有限值;所有 `abs(weight)` 之和 <= `1/margin_rate`;非法值返回错误。
- 策略只能通过 `ctx` 访问当前及历史数据;`Universe` 不暴露未来 bar 的便捷接口。自定义策略若直接索引未来数据,属于违约,代码审查与测试需覆盖。
- 策略不得自行下单、改账本、读文件;所有交易通过目标权重表达。
- 指标状态由策略自己维护,要求摊还 O(1)/bar;禁止每 bar 重算整段历史。

#### 3.3.1 逆波动率权重

同一个权重函数同时用于"策略内多标的"和"多策略组合",避免两套公式:

```rust
pub enum Weighting {
    Equal,
    InverseVol { lookback: usize, floor: f64 },
}

pub fn inverse_vol_weights(
    vols: &[f64],       // 已选标的的波动率,>= 0;0 或非有限视为无效
    directions: &[i8],  // +1 多,-1 空,0 不参与
    gross: f64,         // 目标总敞口,默认 1.0
    floor: f64,
) -> Vec<f64>;
```

计算:

1. `σ_i` 用对数收益 `ln(P_t/P_{t-1})` 的样本标准差(ddof=1),窗口 `lookback`;不足 2 个收益或 σ 非有限则视为无效。
2. `raw_i = 1 / max(σ_i, floor)`;若 `direction_i = 0`,则 `raw_i = 0` 且不进入分母。`floor` 默认 1e-4,防止除零和权重爆炸。
3. 若有效标的(方向非 0 且 σ 有效)少于 2 个,或 `Σ raw = 0`,回退等权并写 warning。
4. `w_i = direction_i × raw_i / Σ_{active} raw_j × gross`;多头为正、空头为负,`Σ |w_i| = gross`。
5. 只在调仓 bar 输出;非调仓 bar 不输出,持仓自然漂移。调仓周期 `rebalance_bars` 由策略配置。

策略内用法:

- 截面动量先按动量选 top_k,再对入选标的做逆波动率分配;方向由动量符号决定。
- `gross` 默认 1.0,仍受 `1/margin_rate` 与现金约束。
- 不做协方差、风险平价、均值方差;这些需要相关矩阵,首版不引入。

多策略组合用法:

- 输入各策略的收益序列,在共同时间戳上对齐;方向全为 +1。
- 同样用 `lookback` 估计波动率、按 `rebalance_bars` 调仓。
- 只做收益层合成,不共享现金;权重之和为 1.0(不做杠杆)。
- 若两个策略时间戳无交集,报错,不做前向填充。

验收:两标的 σ=1%/2%,`gross=1` 时权重为 2/3、1/3;多空方向 +1/-1 时为 2/3、-1/3;σ=0 或历史不足时等权并告警。

### 3.4 风险与执行契约

```rust
pub enum Trigger { Intrabar, Close }

pub struct RiskLeg {
    pub trigger: Trigger,
    pub distance: f64, // 入场价的百分比,0.05 = 5%
}

pub struct RiskConfig {
    pub stop_loss: Option<RiskLeg>,
    pub take_profit: Option<RiskLeg>,
}

pub struct ExecutionConfig {
    pub participation_rate: f64, // 0..1;0 表示不限制
}
```

执行顺序,每个 bar:

1. 开盘:处理上一根 bar 收盘排队的订单,按开盘价 + 滑点成交;检查现金/保证金/手数;成交量参与率限制可导致部分成交,剩余数量顺延。成交量为 0 时所有成交(含风险退出)顺延。
2. 盘中:若启用 `Intrabar`,用当前 bar 的 high/low 检查止损/止盈;先止损后止盈;跳空时用开盘价,否则用触发价;风险退出不受参与率限制,但仍要求 volume > 0。
3. 收盘:按 close 估值,更新权益和回撤;若启用 `Close`,用 close 检查止损/止盈,触发则排队到下一根开盘。
4. 收盘:调用策略,拿到目标权重;与当前持仓比较,生成下一根开盘的订单。
5. 冲突:同一标的同时有风险退出和策略目标时,风险退出优先,忽略该标的的策略目标。

止损/止盈细节:

- 首次开仓时,按成交均价计算绝对止损/止盈价并存入持仓;后续加减仓不改变这两个价格,只有回到空仓后再次开仓才重置。
- 多头止损价 = 首次入场均价 × (1 - distance);空头止损价 = 首次入场均价 × (1 + distance)。
- 多头止盈价 = 首次入场均价 × (1 + distance);空头止盈价 = 首次入场均价 × (1 - distance)。
- 开盘跳空优先:多头 open <= 止损价先按 open 止损;open >= 止盈价先按 open 止盈;空头镜像。只有 open 位于两者之间时,才用 high/low 判断。
- open 位于止损与止盈之间且同一 bar 同时触发两者:按止损成交,报告标记 `ambiguous_bar=true`。
- 跳空穿过止损:多头按 `min(open, stop)` 成交,空头按 `max(open, stop)` 成交。
- `Close` 触发:收盘价穿越后,下一根开盘成交,不按收盘价成交。
- 加减仓不重置止损/止盈;只有回到空仓后再次开仓才重置。首版不做移动止损。
- 风险退出优先成交,不受参与率限制,但不能超过 `bar.volume`;超出部分顺延到下一根。

成本:

- 买入成交价 = 基准价 × (1 + slippage_bps/10000);卖出 = 基准价 × (1 - slippage_bps/10000)。
- 手续费 = `abs(notional) * fee_bps/10000 + fee_fixed`。
- 成交量上限 = `bar.volume * participation_rate`;0 表示不限制;`volume=0` 时不得成交,风险退出也顺延。外汇的成交量常为 tick 计数,默认 `participation_rate=0`,报告披露。
- 最小交易单位:数量向下取整到 `lot_size`;小于一个单位则跳过。

账户:

- `equity = cash + Σ(qty × mark × multiplier)`,空头 qty 为负。
- `gross_exposure = Σ(abs(qty × mark × multiplier))`。
- `required_margin = gross_exposure × margin_rate`。
- 目标权重之和超过 `1/margin_rate` 时,属于策略非法输出,返回 `ExecutionError`,不静默裁剪。
- 目标权重合法但因手续费、手数、现金导致的差额,裁剪到最大允许数量;不足一个单位则拒绝并记录原因。
- 成交后必须满足 `equity >= required_margin` 且 `cash >= 0`;否则视为执行不变量错误。
- 减仓/平仓不受保证金限制。
- 首版要求 `cash >= 0`,因此不支持多头杠杆(现金不能为负);空头保证金占用可用,但不计融券费、资金费率、隔夜利息。
- 首版不建模保证金追缴、强平。

### 3.6 错误契约

```rust
pub enum Error {
    Data(DataError),       // 文件、schema、排序、重复、OHLC、空数据
    Config(ConfigError),   // 缺字段、越界、货币/日历不一致
    Execution(ExecutionError), // 账本不变量、保证金、成交异常
    Report(ReportError),   // 模板、序列化、schema
    Io(std::io::Error),
}
```

约定:

- 库代码不 panic;不使用 `unwrap`/`expect` 处理可恢复错误。
- 错误信息必须含上下文:文件、symbol、ts、参数名、期望/实际。
- CLI 退出码:0 成功;1 运行时错误;2 用法/配置错误;3 数据校验错误。
- 空数据、乱序、重复、负价格、负成交量、NaN/Inf、非法权重都是错误,不是警告。成交量为 0 是合法 bar,只是不产生成交。
- 部分成交、同 bar 止损止盈、保证金裁剪是警告,写入 `warnings` 并在报告展示。

```toml

[[instruments]]

```

`periods_per_year` 可省略;省略时按 `timeframe` 与 `asset_class` 推导,报告记录实际使用值。

截面动量策略在 `[strategy]` 中增加 `lookback`、`top_k`、`rebalance_bars`、`weighting = "inverse_vol"`、`vol_lookback`、`vol_floor`、`gross`;`weighting = "equal"` 时退回等权。

`sweep.toml` 在 `run.toml` 基础上增加:

```toml
[sweep]
objective = "sharpe"
top_k = 20
oos_split = 0.7

[sweep.grid]
fast = [5, 10, 20, 30]
slow = [30, 60, 90, 120]
```

非法组合(如 `fast >= slow`)跳过并计数,不终止整个扫描;若全部非法则报错。

### 3.8 Walk-forward 契约

```rust
pub enum WindowMode { Rolling, Anchored }

pub enum Objective { Sharpe, Cagr, Calmar }

pub struct ParamSeries {
    pub name: String,
    pub values: Vec<f64>, // 每个窗口的最优值
}

pub struct WalkForwardConfig {
    pub mode: WindowMode,
    pub train_bars: usize,     // 训练窗口长度
    pub test_bars: usize,      // 测试窗口长度
    pub step_bars: usize,      // 窗口前进步长,默认 = test_bars
    pub embargo_bars: usize,   // 训练结束与测试开始之间的隔离,默认 1
    pub warmup_bars: usize,    // 训练/测试开始前的指标预热 bar 数,不交易
    pub objective: Objective,  // Sharpe | Cagr | Calmar
}

pub struct WalkForwardWindow {
    pub index: usize,
    pub train_start: usize,
    pub train_end: usize,      // 不含
    pub test_start: usize,     // = train_end + embargo_bars
    pub test_end: usize,       // 不含
    pub best_params: BTreeMap<String, f64>,
    pub is_metrics: Metrics,
    pub oos_metrics: Metrics,
}

pub struct WalkForwardResult {
    pub windows: Vec<WalkForwardWindow>,
    pub oos_equity: Vec<EquityPoint>, // 按日历时间拼接
    pub oos_metrics: Metrics,
    pub param_stability: Vec<ParamSeries>,
    pub skipped_windows: Vec<String>,
}
```

窗口规则:

- 下标基于 `Universe.timeline`,不是每个标的各自的 bar 数;多标的必须已对齐。
- `train_end - train_start >= train_bars`;`test_end - test_start >= test_bars`;`test_bars >= 1`;`step_bars >= test_bars`。
- `step_bars > test_bars` 时窗口之间有空档,OOS 只拼接已测试区间并在报告标记 gap;`step_bars < test_bars` 视为重叠,直接报错。
- `Rolling`:窗口 k 的 `train_start = k × step_bars`,`train_end = train_start + train_bars`,`test_start = train_end + embargo_bars`,`test_end = test_start + test_bars`。
- `Anchored`:`train_start = 0`,`train_end = train_bars + k × step_bars`,其余同上;训练集只增不减。
- 训练集只用于选参:在训练区间内跑网格,按 `objective` 选最优参数;不用测试区间任何数据。walkforward 通过 sweep 的内部接口读取每个参数组的训练指标,不只依赖 top-K 曲线。
- 训练回测同样需要指标预热:窗口开始时先喂 `[train_start - warmup_bars, train_start)`(不足则从 0 开始并记 warning),只更新指标、不交易;训练指标只在 `[train_start, train_end)` 上计算。
- warmup 在测试开始前:取 `[test_start - warmup_bars, test_start)` 只喂策略、更新指标状态,不产生订单;测试区间从 `test_start` 起正常交易。该区间可以落在训练尾部、embargo 或前一个测试窗口,都是已发生的历史数据,不读取未来。
- `warmup_bars` 必须满足 `1 <= warmup_bars <= train_bars + embargo_bars`;不足时报错。warmup 只预热,不计入 OOS 收益。
- 内置策略的 `warmup_bars` 还必须 >= 最长指标窗口(`slow`/`lookback`);不足时返回 Config 错误。自定义策略自行处理历史不足,文档要求其声明所需窗口。
- OOS 拼接:每个窗口取 `[test_start, test_end)` 的日收益,按时间顺序复利;窗口间不重叠时直接拼接;重叠配置在启动时报错,不自动去重。
- `oos_equity` 以 `initial_cash` 为起点,逐日应用上述 OOS 收益;不是把各窗口的绝对权益直接首尾相接,避免窗口间资金基数跳变。
- 最后一个窗口若不足 `test_bars`,默认丢弃并记入 `skipped_windows`;不补齐、不前向填充。
- 选参失败(全部参数非法)时该窗口记入 `skipped_windows`,继续下一个窗口;若没有可用窗口则报错。
- 结果与线程数无关;窗口内扫描可并行,窗口之间默认串行,避免嵌套 rayon。

`walkforward.toml` 在 `sweep.toml` 基础上增加:

```toml
[walk_forward]
mode = "rolling"
train_bars = 756
test_bars = 252
step_bars = 252
embargo_bars = 1
warmup_bars = 60
objective = "sharpe"
```

默认值按日线约 3 年训练、1 年测试、1 年步进;分钟线使用时必须显式改小,引擎只按下标计算,不猜周期。

## 4. 指标与回撤定义

设净值序列 `E_0..E_N`,收益 `r_t = E_t/E_{t-1} - 1`。

| 指标 | 公式/定义 |
| --- | --- |
| 总收益 | `E_N/E_0 - 1` |
| CAGR | `(E_N/E_0)^(365.25/日历天数) - 1` |
| 年化波动 | `std(r, ddof=1) * sqrt(ppy)` |
| Sharpe | `(mean(r) - rf/ppy) / std(r) * sqrt(ppy)`;`std=0` 返回 null |
| Sortino | `(mean(r) - target/ppy) / downside_dev * sqrt(ppy)`;downside_dev 为 `sqrt(mean(min(r-target/ppy,0)^2))` |
| 最大回撤 | `min(E_t / cummax(E) - 1)`,报告为正值 |
| 回撤时长 | 从峰值到恢复的日历天数;未恢复则到序列末尾并标记 |
| Calmar | `CAGR / 最大回撤`;最大回撤为 0 返回 null |
| Ulcer | `sqrt(mean(dd_t^2))`,`dd_t = E_t/cummax(E)-1` |
| 月收益 | 按 UTC 自然月复合 `prod(1+r)-1` |
| 敞口 | 有持仓的 bar 数 / 总 bar 数 |
| 换手 | `Σ abs(成交名义) / 平均权益 / 年数` |
| 胜率 | 盈利的平仓交易数 / 平仓交易数 |
| 盈亏比 | 总盈利 / abs(总亏损) |
| 期望 | 平均每笔交易 PnL |
| 成本拖累 | `Σ费用 / 平均权益 / 年数` |

回撤段:

- 峰值取历史最高净值,谷值为峰值后最低净值,恢复为回到峰值的第一根 bar。
- 输出前 5 段(按深度排序),含峰值/谷值/恢复时间、深度、持续天数、是否恢复。
- `underwater` 序列与净值同长度,写入 JSON,HTML 画图。

DSR:

- 用每期 Sharpe(非年化)、收益偏度 `γ3`、峰度 `γ4`(正态为 3)、试验次数 `N`。
- `SR0 = sqrt(Var(SR_trials)) * ((1-γ)Φ^-1(1-1/N) + γΦ^-1(1-1/(N e)))`,`γ≈0.5772`。
- `DSR = Φ((SR_hat - SR0) * sqrt(T-1) / sqrt(1 - γ3*SR_hat + (γ4-1)/4*SR_hat^2))`。
- `N=1` 时 `SR0=0`;`N` 为实际运行的参数组合数,跳过的不计。
- 报告 DSR 为概率;同时展示试验次数、SR 方差、偏度、峰度。
- 这是近似校正,参数网格高度相关时有效试验数小于 N;报告注明局限。

样本外:

- 按时间切分,默认前 70% 为样本内,后 30% 为样本外。
- 用样本内目标值选最优参数,报告该参数在样本外的指标。
- 同时报告样本内外排名相关性;排名剧烈变化是过拟合信号。
- walk-forward 与单次 70/30 是两种模式:前者多窗口、训练集逐窗选参;后者只切一刀。报告字段分开,不把 70/30 的 OOS 指标标成 walk-forward。
- `walk_forward` 为 null 表示本次未运行 walk-forward,不是“运行失败”。

## 5. 性能设计

目标算式:

- 500 标的 × 2500 bar × 1000 参数 = 1.25e9 bar 步。
- 600 秒完成,需要 2.08e6 bar 步/秒(全机),8 核即 2.6e5/核。
- 500000 个任务,600 秒,每任务预算 1.2 ms;任务启动、策略构造、缓冲区分配必须远低于此。
- 单次回测 500 标的 × 2500 bar = 1.25e6 步,2 秒需要 6.25e5 步/秒,余量充足。
- walk-forward 计算量约等于窗口数 × 单窗网格;不套用 AC12 的 10 分钟目标,报告记录实际耗时与窗口数。

设计手段:

1. 数据 SoA + `Arc<Universe>`,只加载一次;所有任务共享只读数据。
2. 热循环零分配:每个 worker 用 `map_init` 持有可复用的 `Vec<TargetPosition>`、`Vec<PendingOrder>`、权益缓冲。
3. 策略状态摊还 O(1):双均线用滚动和,突破用单调队列/环形缓冲,截面动量按调仓日排序。
4. 每任务只返回指标与元数据;完整权益/成交只保留 top-K 和明确要求的任务。
5. 并行粒度是任务,不嵌套 rayon;线程数默认 `auto`,`--threads N` 可覆盖。
6. 结果顺序由任务索引决定,不依赖 HashMap 迭代;保证并行/串行一致。
7. 指标一趟算完:收益、峰值、回撤、月收益、交易统计在同一个循环或少量循环中完成;不做多次全量遍历。
8. 基准用 criterion + `bench` 命令;阶段 1 就测,不等到最后。

### 5.1 线程与内存自适应

默认配置:

```toml
[run]
threads = "auto"        # auto | 整数
memory_limit_gb = 0     # 0 = 自动检测
```

决策顺序:

1. CPU 上限:`std::thread::available_parallelism()`,失败时回退 1 并告警。该值受亲和性与 cgroup cpuset 影响,但不一定反映容器 CPU 配额。
2. 额外读取 cgroup v2 `/sys/fs/cgroup/cpu.max`,若 quota 不是 `max`,可用核数 = `ceil(quota / period)`;再取两者较小值。
3. 内存上限:依次读 cgroup v2 `memory.max`、cgroup v1 `memory.limit_in_bytes`、`/proc/meminfo` 的 `MemAvailable`;取最小值,未知则只用 CPU 约束并告警。
4. 预留:从可用内存中保留 `max(2 GB, 10%)` 给系统、页缓存和报告生成。
5. 单 worker 预算 = 数据分片常驻 + 任务缓冲(权益、成交、订单、策略状态);日线按 64 MB 估,分钟线按数据量实测估。
6. 若 `mem_avail - reserve < worker_budget`,直接返回 Config 错误(所需/可用内存);否则线程数 = `min(cpu_avail, max(1, floor((mem_avail - reserve) / worker_budget)))`;结果与线程数无关。
7. `--threads N` 与 `--memory-limit-gb X` 显式覆盖自动值;显式值超过检测上限时警告但不静默放大。
8. `bench --scale` 在固定合成负载上跑 1/2/4/8 线程,打印每档吞吐、峰值内存与推荐线程数;推荐值只用于调参,不写死。

当前开发机实测:cgroup v2 存在,`cpu.max = max 100000`(无配额),`memory.max = max`,`nproc = 2`;自动检测应得到 2 线程,而不是把宿主核数当成可用核数。目标机 8 核 32 GB 上,若单 worker 预算 64 MB,内存允许 400 以上线程,实际由 CPU 限制为 8。

### 5.2 内存估算

- 数据:125 万 bar × 6 列 × 8 字节 ≈ 60 MB。
- 单任务权益:2500 × 8 ≈ 20 KB;top-20 曲线 < 2 MB。
- 50 万任务指标:按 200 字节/任务 ≈ 100 MB。
- 峰值目标 < 8 GB,余量充足。

- 笛卡尔积、非法组合跳过、目标排序、top-K 完整结果。
- 并行/串行一致;`threads = "auto"` 与 `--threads N` 覆盖。
- 内存上限检查:启动前按 worker 预算决定线程数,不足一个 worker 时报错。
- 结果元数据记录实际线程数、检测到的 CPU/内存与是否被覆盖。
- 不做分布式。

验收用例:

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| T4.1 串并行一致 | 100 组参数,2 线程 vs 1 线程 | 每个任务指标误差 <= 1e-12,顺序一致 |
| T4.2 确定性 | 同配置跑两次 | 规范化结果哈希一致(排除时间、线程数) |
| T4.3 非法组合 | fast=60,slow=20 | 跳过并计数;不 panic |
| T4.4 内存 | 1000 组,top_k=20 | 只保留 20 条完整曲线;峰值内存记录 |
| T4.5 缩放基准 | 500×2500×1000 合成 | 2 核实测 + 8 核外推;目标 < 10 分钟,未验证则标注 |
| T4.6 任务开销 | 500k 空任务 | 每任务平均开销 < 1.2 ms |
| T4.7 单次全量 | 500 标的 × 2500 bar,单策略 | 端到端 < 2 秒(当前 2 核;目标机应更快) |
| T4.8 自动线程 | 100 组参数,`auto`、1、2 线程 | auto 解析为 2;三组指标误差 <= 1e-12,输出顺序一致 |
| T4.9 内存上限 | `--memory-limit-gb` 低于单 worker 预算 | 启动前返回 Config 错误,含所需/可用内存;不触发 OOM |

风险:任务开销、内存、并行确定性。回退:减少 top-K、分批写结果、改用任务分块。

### S5 指标与报告

目标:完整指标、回撤段、月度热力图、交易/成本分析、样本外、walk-forward、DSR、HTML/JSON。

输入:S1–S4 结果、`fixtures/report_case.json`、`fixtures/walkforward.toml`。

输出:`report.html`(离线)、`result.json`(含 `walk_forward`)、`sweep.csv`。

范围:

- 指标公式与空值处理。
- 回撤前 5 段、水下曲线。
- 月度热力图、成本、换手、交易明细。
- 参数敏感性:top 100、边际效应、2 参数热力图。
- 样本外 70/30、DSR。
- walk-forward:窗口表、训练集选参、embargo、warmup、OOS 拼接、参数稳定性。
- 报告固定 10 个章节,walk-forward 放在“样本外与稳健性”内;不做 PDF。

### S6 健壮性与交付

目标:输入校验、错误信息、CLI、配置、README、干净克隆复现、安全检查。

输入:全部夹具、非法夹具、干净目录。

输出:全部测试通过;`cargo fmt/clippy/test` 通过;README 可复现。

范围:

- 空/乱序/重复/负价/零量/NaN/Inf/非法权重/参数越界。
- walk-forward 窗口非法:train/test 为 0、warmup 越界、embargo 越界、step < test、窗口不足。
- 线程/内存参数非法:负数、超过检测上限、内存不足一个 worker。
- 错误信息含上下文;退出码。
- 配置默认值与校验。
- README、示例配置、依赖锁定、许可与第三方声明。
- `cargo audit`/`cargo deny`(若可用)。
- 仓库无密钥、无个人绝对路径。

风险:时间不足;依赖审计工具安装。回退:安全审计标注"未运行+原因",不伪造。
