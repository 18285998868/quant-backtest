# 01 需求规格

日期:2026-11-16
状态:阶段二产出,待确认点拍板

## 1. 一句话目标

用纯 Rust 构建一个日线级、多标的、可做空、支持参数扫描的策略回测引擎,让一次"500 标的 × 10 年 × 1000 组参数"的实验在 8 核机器上 10 分钟内跑完,并输出可复核的中文 HTML/JSON 报告。

真实问题不是"缺一个回测器",而是:

1. 研究循环慢。参数扫描和多标的实验耗时太长,想法验证频率低。
2. 结果不可信。成交假设、成本、做空、止损和组合资金规则不透明,报告无法复核。
3. 参数扫描越快,过拟合越快。报告需要同时给出样本外结果和搜参校正后的显著性,而不是只给最高 Sharpe。

## 2. 背景与现状

- 数据下载模块 `data-downloader` 与数据加载模块 `data-reader` 已由用户单独实现,不在当前开发环境。
- 当前环境为 Docker 容器,Ubuntu 24.04,2 核 12 GB,Rust 1.100.0,可运行 cargo。
- 目标机器为 8 核以上、32 GB 内存;当前机器只用于正确性验证和小规模基准。
- 用户市场范围:加密、美股、外汇;允许做空。
- 用户已确认:收盘出信号、次日开盘成交;止盈止损除 high/low 触发外,还要支持收盘价判断;策略采用"内置参数化策略 + Rust trait 自定义策略"两条腿;报告输出 HTML + JSON;纯 Rust,不做实盘。

### 3.2 不做什么

| 不做 | 原因 |
| --- | --- |
| tick、盘口、逐笔成交、排队模拟 | 当前目标是日线策略研究,不是 HFT;`hftbacktest` 类工具解决的是另一问题 |
| bar 内价格路径推断 | 仅有 OHLC 无法知道先后;采用保守规则并明确披露 |
| 永续资金费率、期货展期、期权 Greeks | 需求未提;先按现货/股票/外汇即期建模 |
| 融券费用、借券可得性、美股 T+1 结算、税费 | 需求未提;日线研究用现金账户近似,报告中列为已知限制 |
| 分红送转的逐笔处理 | 美股使用复权价,按总收益近似;加密/外汇不涉及 |
| 跨币种实时换算 | 一次回测只允许一种计价货币;跨资产类别只在收益层合成 |
| 多日历混合组合(美股 + 加密同一账户) | 交易日历和估值时点不同,复杂度高;先按资产类别分开跑,再合成 |
| 实盘、仿真撮合、交易所对接 | 用户明确只做研究验证 |
| 自研 DSL、脚本引擎、热重载 | 内置策略用 TOML,复杂策略写 Rust;避免造语言 |
| 分布式、GPU、数据库 | 单机 8 核以上已能满足目标;先不引入 |
| PDF 报告、邮件、Web 服务 | HTML 单文件已满足评审;PDF 牵涉排版依赖 |
| 组合优化(均值方差、风险平价、协方差收缩) | 首版只做等权/固定权重/逆波动率;逆波动率不使用协方差 |

有意省略的扩展点:策略注册表、插件动态加载、多账户、订单类型扩展、事件总线。没有需求支撑,首版不加。

## 4. 用户与场景

主要用户是策略研究者本人和团队评审者。

典型流程:

1. 用 `data-reader` 导出规范化日线数据。
2. 写一个 TOML 配置,选择内置策略或自定义 Rust 策略。
3. 跑单次回测,检查交易明细和回撤,确认成交与成本假设符合预期。
4. 跑参数扫描,查看参数敏感性、样本外表现和 DSR。
5. 把 HTML 报告发给团队评审,JSON 留作二次分析。

## 5. 关键需求解释

### 5.1 组合回测如何实现

采用两层,避免把"策略组合"和"多标的共享账户"混成一个黑盒。

第一层,引擎内组合:

- 一个策略实例 × 一个标的池 × 一个共享账户。
- 策略每个 bar 输出各标的目标权重,引擎统一换算数量、检查现金/保证金、按下一根 bar 开盘成交。
- 适用于截面动量、多标的轮动、同一策略的资金共享。
- 标的池必须使用同一交易日历、同一计价货币。不同时拒绝并给出明确错误。

第二层,系统级组合:

- 多个策略、多个资产类别分别独立回测,得到各自的净值/收益序列。
- 组合器按等权、固定权重或逆波动率合成收益序列。
- 不共享现金,不处理策略间资金竞争;报告明确标注这是"收益层组合",不是统一账户。
- 这样可以把美股、加密、外汇分开跑,避免跨日历、跨币种和保证金的复杂度。

参数扫描对以上两种组合都适用:每个(策略, 参数组, 标的池)是独立任务,任务内多标的共享账户,任务间并行。

### 5.2 "回撤模块"的定位

回撤不是独立计算引擎,而是指标模块的一部分。输入是净值曲线,输出是回撤序列、最大回撤、持续/恢复时间、前 N 段回撤和 Ulcer 指数。计算复杂度 O(n),相对回测主循环可以忽略。参数扫描的瓶颈在数据重复读取、指标重算、成交模拟和内存分配,不在回撤统计。

### 5.3 策略是写 rs 还是写条件

两条腿,边界明确:

- 内置策略:双均线、通道突破、截面动量,参数写在 TOML,不写代码。
- 复杂策略:实现 `Strategy` trait,编译进二进制。策略代码拥有完整 Rust 能力,但必须遵守"只能看到当前及历史 bar"的契约。
- 不提供通用条件表达式、脚本语言或热重载。原因:通用条件最终会变成自研 DSL,维护成本和出错面远大于收益。

### 5.4 为什么把 walk-forward 放进首版

单次 70/30 切分只产生一个样本外结果,无法区分"参数稳定"与"恰好某段行情适配"。walk-forward 用多个训练/测试窗口回答三个问题:样本外是否持续、最优参数是否漂移、换窗口后收益分布是否稳定。

首版规则:默认 rolling,训练 756 bar、测试 252 bar、步进 252 bar、embargo 1 bar、warmup 60 bar;每个窗口只用训练集选参,测试集不参与;OOS 按时间拼接。报告披露窗口参数,并明确 walk-forward 不是收益保证。PBO、SPA 等更复杂的多重检验不在首版,DSR 只校正搜索次数。

### 5.5 性能如何按机器自适应

默认 `threads = "auto"`:先取 `available_parallelism()`,再读 cgroup 的 CPU 配额和内存上限,预留系统内存后按单 worker 预算决定线程数;`--threads N` 与 `--memory-limit-gb` 可覆盖。线程数只影响耗时,不影响结果;`bench --scale` 打印 1/2/4/8 线程吞吐和推荐值。当前开发机 2 核 12 GB 只做正确性与缩放外推,目标机 8 核 32 GB 的 AC12 仍需实测。

| ID | 假设 | 影响 | 若假设错误 |

## 9. 风险与未知

| 风险 | 等级 | 说明 | 缓解 |
| --- | --- | --- | --- |
| 数据契约不匹配 | 高 | 两个数据模块不在本机,字段/格式未知 | 先定规范 schema;提供 CSV/Parquet 适配与校验;尽早用真实样本验证 |
| 成交语义错误 | 高 | 未来函数、止损同 bar 歧义、跳空处理 | 手算夹具;表驱动测试;报告披露假设 |
| 性能不达标 | 中 | 每任务分配、指标重算、线程/内存误判 | 热路径零分配;rayon map_init;`--threads auto` + 内存预算;早期基准;缩放验收 |
| 组合/保证金会计错误 | 高 | 做空、现金、保证金交互复杂 | 独立账本测试;不引入杠杆;与手算逐笔对账 |
| 逆波动率权重失真 | 中 | 低波动资产权重过大;σ 估计窗口短 | floor、lookback 可配;σ=0/历史不足回退等权;报告展示权重与换手 |
| Walk-forward 计算量/窗口不足 | 中 | 网格 × 窗口数成倍增加;训练/测试切分不当会泄漏 | 窗口参数校验;embargo;warmup;并行;先跑 3 窗口小规模 |
| 范围膨胀 | 高 | 报告、组合、walk-forward、数据适配都可能膨胀 | 明确不做清单;阶段门禁;首版报告固定章节 |
| 过拟合 | 高 | 扫描 1000 组必然出现高 Sharpe | 样本外 + walk-forward + DSR + 参数敏感性;报告不承诺策略有效 |
| 多币种/多日历 | 中 | 首版不支持,用户可能误用 | 启动时拒绝混合货币/日历;文档醒目说明 |
| 分钟线内存 | 中 | 500 标的 × 10 年 1m 约 24 GB,超过 8 GB 预算 | M1 输出常驻内存估算并在超限时告警;分块/按标的加载留待后续 |
| 线程/内存自动检测误判 | 中 | cgroup/VM 限额可能被高估或低估 | 读取 cgroup v2/v1 与 `/proc/meminfo`;保留 `--threads`/`--memory-limit` 覆盖;bench 打印检测值 |
| 依赖升级破坏 | 中 | Polars/Arrow API 变动快 | 锁定版本;Cargo.lock 提交;构建时核对官方文档 |
| 单人 5 周不足 | 中 | 正确性 + 性能 + walk-forward + 报告 | 阶段切分;每阶段可交付;必要时砍报告非核心章节 |

未知项:

1. `data-reader` 的实际输出格式、字段、复权方式、时区。
2. 用户真实数据规模是否超过 500 标的 × 10 年。
3. 用户对杠杆、保证金、手续费的真实设定。
4. 目标机具体型号与核心数;自动检测只能给近似值。
5. 分钟线/小时线的优先级、数据规模与可接受内存;当前按日线设计。
6. walk-forward 的窗口长度、调仓频率与计算预算。

## 10. 术语

| 术语 | 含义 |
| --- | --- |
| bar | 一根 K 线,含 open/high/low/close/volume |
| 信号 bar | 策略读取并产生信号的 bar,记为 t |
| 成交 bar | 信号之后第一根可交易 bar,记为 t+1 |
| 目标权重 | 目标持仓名义价值 / 账户权益;负数为空头 |
| 回撤 | 权益从历史峰值下跌的幅度,报告为正值 |
| 水下曲线 | 当前权益相对历史峰值的百分比差 |
| DSR | Deflated Sharpe Ratio,对多次搜索后的 Sharpe 做显著性校正 |
| 样本外 | 未参与参数选择的时间段 |
| 共享账户 | 同一策略的多个标的共用一份现金和保证金 |
| walk-forward | 滚动或扩展训练窗口,用训练集选参,在紧随其后的测试窗口评估 |
| embargo | 训练结束与测试开始之间强制间隔的 bar 数,防止边界信息泄漏 |
| warmup | 正式测试前只更新指标、不交易的一段 bar |
| 逆波动率权重 | 按 `1/σ` 分配权重,使低波动标的占比更高;不做协方差 |
| 自动线程 | 按 CPU 配额与内存预算推导线程数,可被显式参数覆盖 |
