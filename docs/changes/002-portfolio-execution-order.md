# 002 组合开盘成交顺序

## 动机

S3 引入共享现金账户后,同一根 bar 可能同时有多个标的的订单。
若按标的顺序成交,先买后卖可能让卖出释放的现金来不及参与买入,导致订单被裁剪;
先处理风险退出还是策略目标也会因标的顺序而不同。

## 影响范围

- `process_open` 先按成交方向分组:卖出方向订单先执行,买入方向订单后执行。
- 同一方向内按优先级成交:风险退出 > 减仓 > 开仓/加仓(含反向翻转),同级按标的 ID 升序。
- 单标的回测至多只有一个挂单,行为不变。
- 不改变目标权重语义、成本、手数或风险价规则。

## 替代方案

1. 保持标的顺序。实现简单,但结果依赖 `instruments` 排列,组合换仓时可能误裁剪,弃用。
2. 同一 bar 内按组合层面同时求解现金分配。需要联立所有订单与费用,首版复杂度和可解释性都不合适,暂不做。
3. 只把风险退出提前,不做先卖后买。短空头止损回补仍可能因现金不足被裁剪,弃用。
4. 同一方向内只按标的 ID,不区分减仓与开仓。回补或减仓释放的保证金来不及参与后续开仓,组合换仓可能被误裁剪,弃用。

## 回退计划

恢复 `process_open` 的标的顺序循环即可;目标权重与账本结构不受影响。
